# 产品设计说明：My Weibo

## 愿景与目标

My Weibo 致力于成为轻量、易部署的微型微博平台，核心聚焦以下三点：

- **单管理员叙事**：支持小型内容团队或个人博主快速发布短内容、附带图片，并维护权威信息流。
- **低门槛互动**：允许注册用户与访客轻松评论、点赞，打造活跃的受众互动体验。
- **运维简洁**：整体运行在 Bun 之上，构建产物小、部署步骤短，开发者体验友好。

## 用户角色

- **管理员作者**：通过专用后台登录，负责发布、修改、删除微播，管理图片资源并执行互动内容的审核。
- **注册读者**：使用邮箱注册或登录，可点赞、评论、维护个人昵称信息，并可编辑或删除自己的互动。
- **访客用户**：无需登录即可浏览信息流；若提供昵称与邮箱，也可留下评论。

## 核心流程

### 管理员

1. **认证与会话**：调用 `/api/auth/admin-login` 获取 `my_weibo_session` 会话 Cookie。
2. **内容运营**：管理员专属接口允许创建/编辑/删除微播，上传图片并调整内容顺序。
3. **互动管理**：可删除任意评论、清空点赞，维护内容秩序。

### 注册读者

1. **快速建号**：通过邮箱 + 密码首次登录时自动开户，若未指定昵称则以邮箱前缀生成。
2. **互动体验**：可点赞/取消点赞、发表评论，并在权限允许的情况下修改或撤回自己的评论。
3. **会话保持**：同一会话 Cookie 负责所有后续请求，刷新页面无需重新登录。

### 访客

1. **公开浏览**：无需登录即可获取微播列表与详情。
2. **匿名评论**：提供昵称与邮箱即可留言，服务端负责基础校验。
3. **内容消费**：可查看管理员上传的图片、阅读互动区。

## 功能概览

| 功能 | 面向用户 | 说明 |
| --- | --- | --- |
| 微播发布 | 管理员 | 支持文本 + 图片的帖文，存储于 Drizzle ORM 定义的 SQLite 表，通过 Elysia API 暴露。 |
| 评论系统 | 注册用户 + 访客 | 每条微播附带评论列表，提供服务端校验与审核能力。 |
| 点赞机制 | 注册用户 | 保证单用户单帖唯一点赞，可重复切换状态。 |
| 文件上传 | 管理员 | 图片上传至 `UPLOADS_DIR`，限制大小与 MIME 类型，由服务端静态托管。 |
| 主题切换 | 所有用户 | 使用 `next-themes` 在客户端切换明/暗模式。 |
| 实时能力（预留） | 后续规划 | 依赖 `socket.io`，未来可扩展为实时推送或在线状态。 |

## 数据模型（Drizzle）

- **User**：记录用户名、邮箱、密码哈希、`isAdmin` 标识。
- **Session**：存储会话 Token 与过期时间，关联用户。
- **Microblog**：微播正文，关联图片、点赞、评论。
- **Image**：图片元信息（URL、alt 文案），归属微播。
- **Like**：以微播 ID + 用户 ID 作为唯一键的点赞记录。
- **Comment**：评论内容、作者 ID（可空）、访客昵称邮箱、时间戳。

## 技术选型

- **Bun + Elysia**：高性能、TypeScript 友好的服务端栈，插件生态轻量。
- **Vite + React**：现代前端构建工具，热更新迅速，产物体积小。
- **Drizzle ORM**：轻量类型安全 ORM，直接使用 TypeScript 定义表结构。
- **Tailwind CSS v4**：实用类风格系统，配合组件库快速搭建 UI。

## 部署说明

- 执行 `bun run build` 后，将得到 `build/server.js`（服务端）与 `build/client/`（前端静态资源）。
- 生产环境建议将 `UPLOADS_DIR` 指向持久化存储路径（默认 `storage/uploads`）并赋予写权限，避免将真实上传内容打包进构建产物。
- 静态资源目录可通过 `CLIENT_ASSETS_DIR` 覆写；若使用容器，可将其挂载为只读卷。
- 服务端启动会自动检测并创建 SQLite 表结构，更新模型时需同步调整 `src/lib/db.ts` 中的初始化 SQL。
